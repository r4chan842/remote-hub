# مرزهای انطباق

این سند بخش جدایی‌ناپذیر معماری است، نه یک یادداشت حقوقی کنار پروژه.

## ۱. GitHub Actions چه کاری انجام می‌دهد

فقط کارهایی که به خودِ پروژهٔ نرم‌افزاری همین ریپازیتوری مربوط‌اند:

- بیلد اپلیکیشن Android و Windows
- اجرای تست‌های واحد
- رندر و اعتبارسنجی صفحات UI
- بسته‌بندی و انتشار Release با تگ نسخه
- اتوماسیون provision کردن زیرساخت روی سرویس مجاز، به‌عنوان بخش deployment همان پروژه

## ۲. GitHub Actions چه کاری انجام نمی‌دهد

- میزبانی دسکتاپ ریموت شخصی
- اجرای نشست RDP روی رانر
- تبدیل رانر به VPS
- دور زدن سقف زمانی job یا سهمیهٔ دقیقه
- اجرای دائمی یا زمان‌بندی‌شده برای نگه داشتن یک نشست زنده

بر اساس شرایط رسمی GitHub، استفاده از رانرهای میزبانی‌شده برای «هر فعالیت نامرتبط با تولید، تست، استقرار یا انتشار پروژهٔ نرم‌افزاری همان ریپازیتوری» مجاز نیست و می‌تواند به توقف job، غیرفعال شدن ریپازیتوری یا تعلیق حساب منجر شود.

## ۳. زیرساخت ریموت کجا اجرا می‌شود

روی سرویسی که دسترسی ریموت را مجاز می‌داند:

- ماشین ویندوزی خود کاربر
- VPS ابری با API رسمی
- رایانهٔ سازمانی با مجوز دسترسی

اپ یک لایهٔ `RemoteProvider` دارد تا مقصد قابل تعویض باشد. مقصد پیش‌فرض، سرویس مجاز است، نه رانر GitHub.

## ۴. محدودیت‌هایی که در UI نمایش داده می‌شوند

- حداکثر زمان هر job: ۶ ساعت
- سهمیهٔ دقیقهٔ ماهانه و تعداد job هم‌زمان
- از بین رفتن دادهٔ روی ماشین پس از پایان نشست
- تغییر آدرس و گذرواژه در اجرای مجدد

این‌ها در صفحهٔ داشبورد، صفحهٔ ساخت سرور و صفحهٔ جزئیات سرور به کاربر نشان داده می‌شوند. هیچ ادعای «دائمی» یا «نامحدود» در محصول وجود ندارد.

## ۵. ریپازیتوری عمومی و دادهٔ حساس

ریپازیتوری عمومی است، پس لاگ‌ها و فایل‌ها برای همه قابل مشاهده‌اند. قواعد اجباری:

| داده | قاعده |
|---|---|
| توکن GitHub | هرگز در ریپو، لاگ یا بکاپ |
| Auth Key تیل‌اسکیل | فقط به‌صورت Secret رمزنگاری‌شده |
| گذرواژهٔ RDP | تولید در اپ، ارسال به‌عنوان Secret، هرگز چاپ در لاگ |
| بکاپ | رمزنگاری سمت کلاینت پیش از آپلود |
| کلید رمزنگاری بکاپ | فقط روی دستگاه کاربر، هرگز آپلود |

## ۶. احراز هویت

فقط روش‌های رسمی:

- GitHub Device Authorization Flow
- GitHub Personal Access Token با مجوز حداقلی
- Tailscale API access token یا OAuth client برای ساخت auth key کوتاه‌عمر

استخراج توکن یا کوکی از WebView انجام نمی‌شود. گوگل ورود OAuth در WebView را مسدود می‌کند و این روش مرز امنیتی را می‌شکند.

## ۷. شفافیت کد

- بدون obfuscation
- بدون نام‌گذاری فریبنده برای پنهان کردن عملکرد workflow
- اکشن‌های خارجی پین‌شده به SHA کامل
- `permissions` صریح و حداقلی در هر job
- کاربر می‌تواند پیش از اجرا، محتوای workflow را ببیند

## ۸. توکن اشتراک‌گذاشته‌شده در گفت‌وگو

توکنی که در چت ارسال شد فقط برای ساخت ریپازیتوری و اجرای CI همین پروژه استفاده شد و در هیچ فایلی ذخیره نشده است. چون در گفت‌وگو قرار گرفته، باید پس از پایان کار در تنظیمات GitHub باطل و با یک توکن جدید جایگزین شود.
